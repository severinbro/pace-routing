## System Architecture

The platform is split into 8 Docker containers that share a bridged network (`pace_net`):

| # | Container | Image | Role |
|---|-----------|-------|------|
| 1 | `pace_db` | `postgres:15-alpine` | Permanent PostgreSQL database |
| 2 | `pace_redis` | `redis:7-alpine` | Real-time message broker (sensor snapshots + DB queue) |
| 3 | `pace_tiles` | `overv/openstreetmap-tile-server` | Offline OSM map tile server |
| 4 | `pace_web` | (built from `Dockerfile`) | Django app served by Gunicorn (4 workers × 2 threads) |
| 5 | `pace_worker` | (built from `Dockerfile`) | `sensor_manager.py` — polls I2C/USB sensors every second |
| 6 | `pace_pgadmin` | `dpage/pgadmin4` | Optional database management UI |
| 7 | `pace_db_writer` | (built from `Dockerfile`) | `manage.py save_sensor_data` — drains Redis queue into PostgreSQL |
| 8 | `pace_nginx` | `nginx:alpine` | TLS termination — the only public-facing HTTPS endpoint |

### Request & data flow

```
Smartphone (https://10.42.0.1:8000)
        │  TLS handshake (self-signed cert)
        ▼
NGINX (host:8000 → container:443)  ── terminates TLS, sets X-Forwarded-Proto
        │  plain HTTP
        ▼
Gunicorn (web:8000, 4 workers × 2 threads)  ── Django app
        │
        ├── PostgreSQL (db:5432)  ── surveys, users, persisted sensor rows
        └── Redis (redis:6379)    ── live sensor snapshot + write queue

sensor_manager.py (pace_worker)
        │  polls I2C bus 1 (BME280, ENS160, LIS3DH, SAM-M10Q GNSS)
        │  polls I2C bus 2 (PMSA003I particulate matter)
        │  samples USB microphone (noise dB)
        │  reads phone GNSS from Redis ('gnss_phone')
        ▼
Redis:  'sensor_measurements'  (overwritten every 1s — feeds the dashboard)
        'sensor_db_queue'      (pushed every 5s — drained by db_writer)
                ▼
save_sensor_data command (pace_db_writer)  →  PostgreSQL sensor tables
```

### Port mapping (host → container)

| Host port | Container port | Service | Purpose |
|-----------|----------------|---------|---------|
| `8000` | `443` | nginx | **HTTPS — main entry point for participants & admin** |
| `8081` | `80` | nginx | HTTP → 301 redirect to HTTPS |
| `8080` | `80` | tileserver | Offline map tiles (used by the Leaflet map) |
| `5050` | `80` | pgadmin | Database management UI |
| `5432` | `5432` | db | PostgreSQL (only needed for local debugging) |

> **Why HTTPS on port 8000?** The browser Geolocation API (used to push the admin phone's GPS to the Pi) only works in a [secure context](https://developer.mozilla.org/en-US/docs/Web/Security/Secure_Contexts). NGINX terminates TLS with the self-signed certificate generated by `generate_cert.sh` and proxies plain HTTP to Gunicorn. Django trusts the `X-Forwarded-Proto: https` header (see `SECURE_PROXY_SSL_HEADER` in `pace/settings.py`) so secure cookies and CSRF work correctly.

## Sensor hardware

The `sensor_worker` container polls the following sensors. The Pi 5's I2C bus 1 and bus 2 plus the USB microphone are passed into the container via device mappings in `docker-compose.yml`.

| Sensor | Bus | Measures | Django model |
|--------|-----|----------|--------------|
| PiicoDev BME280 | I2C bus 1 | Temperature, humidity, pressure | `AtmosphericMeasurement` |
| PiicoDev ENS160 | I2C bus 1 | AQI, TVOC, eCO2 | `AirQualityMeasurement` |
| PiicoDev LIS3DH | I2C bus 1 | Acceleration X/Y/Z, angles | `AccelerometerMeasurement` |
| PMSA003I | I2C bus 2 | PM1.0, PM2.5, PM10 | `ParticulateMeasurement` |
| SAM-M10Q GNSS | I2C bus 1 | Latitude, longitude, altitude, satellites | `GNSSSensorMeasurement` |
| USB microphone | `/dev/snd` | Noise level (dB) | `NoiseMeasurement` |
| Admin smartphone | Browser API | Latitude, longitude, altitude, accuracy | `GNSSPhoneMeasurement` |

Two GNSS sources are merged into every sensor snapshot:
1. **Phone GNSS** — pushed by the admin smartphone's browser via the Geolocation API to `/api/update-gnss/`, stored in Redis under `gnss_phone`.
2. **Sensor GNSS** — read directly from the SAM-M10Q over I2C.

Only admin (`is_staff`) accounts may push GNSS fixes, so participant phones never interfere.

## Django application

### URL routes (`data_cube/urls.py`)

| Path | Access | Description |
|------|--------|-------------|
| `/` | login required | Environmental survey (11-question, 7-point Likert, 3 phases) |
| `/login/` | public | Role-based login (admin → admin home, participant → survey) |
| `/sign-up/` | public | Self-service participant account creation |
| `/admin-home/` | admin | Landing page with links to dashboard, map, data browser |
| `/create-user/` | admin | Create a new participant account |
| `/map/` | admin | Offline Leaflet map (tiles from `pace_tiles`) |
| `/dashboard/` | admin | Live sensor telemetry grid (AJAX to `/api/latest-sensors/`) |
| `/data-browser/` | admin | Tabbed CMS-style tables of the last 200 rows per sensor |
| `/export-gpkg/` | admin | Download all sensor data as a GeoPackage (7 tables, QGIS/ArcGIS ready) |
| `/export-survey-json/` | admin | Download all survey responses as JSON (one entry per survey) |
| `/api/latest-sensors/` | public | JSON snapshot of the latest Redis sensor reading |
| `/api/update-gnss/` | admin (POST) | Receive phone GNSS fix + sync Pi system clock |
| `/admin/` | admin | Built-in Django admin |

### Survey

The environmental survey (`EnvironmentSurvey` model) is served at the root URL `/`. It has 11 questions on a 7-point Likert scale, split into 3 phases:

- **Phase 1 — Environmental features (q1–q7):** Noise, Air Quality, Air Temperature, Aesthetics, Diversity, Urban Design, Accessibility.
- **Phase 2 — Personal perception (q8–q10):** Safety, Enjoyment, Stress.
- **Phase 3 — Overall comfort (q11):** A single comfort rating.

On submission, the current phone GNSS fix is read from Redis and saved as a `GNSSPhoneMeasurement`, which is linked to the survey via a `OneToOneField` (`gnss_snapshot`). This lets you later join each survey response to the exact sensor state at that moment.

### GeoPackage export

`/export-gpkg/` joins all 7 sensor tables on their shared `id` primary key (they are written together per reading by `save_sensor_data.py`), uses the phone GNSS latitude/longitude as point geometry, and streams a `.gpkg` file that opens directly in QGIS or ArcGIS. The sensor GNSS table (`GNSSSensorMeasurement`) is included as additional columns alongside the phone GNSS geometry.

### Survey JSON export

`/export-survey-json/` streams all `EnvironmentSurvey` responses as a `.json` file. Each submitted survey is its own entry, containing the survey id, timestamp (ISO-8601, set at transmission time via `auto_now_add`), username, all 11 Likert responses (`q1`–`q11`), and the id of the linked GNSS phone snapshot.

## How to run

### 1. Hardware & OS configuration

The Pi 5 needs both I2C buses enabled and the USB power limit unlocked (for the BrosTrend Wi-Fi adapter and USB microphone).

1. Open the boot configuration file:
```bash
sudo nano /boot/firmware/config.txt
```

2. Find the optional hardware interfaces section and ensure both I2C lines are active:
```ini
# Uncomment some or all of these to enable the optional hardware interfaces
dtparam=i2c_arm=on
dtoverlay=i2c2,baudrate=100000
```

3. Scroll to the very bottom and add the USB power override under the `[all]` tag:
```ini
[all]
usb_max_current_enable=1
```

4. Save, exit (`CTRL+O`, `Enter`, `CTRL+X`), and **reboot the Pi** entirely.

### 2. Wi-Fi hotspot & driver setup

The Pi broadcasts its own offline network so participants can connect in the field without internet.

1. Create the hotspot (a USB Wi-Fi dongle is recommended for range and stability):
```bash
sudo nmcli device wifi hotspot ifname wlan1 ssid "pace" password "pace2026"
sudo nmcli connection modify Hotspot connection.autoconnect yes connection.autoconnect-retries 0
```

> **Note:** It is recommended to add a USB-WiFi dongle (e.g. [BrosTrend AX900 Mini](https://www.brostrend.com/products/ax7l)) to emphasize the WiFi signal for more reach and stability. The hotspot's gateway IP is `10.42.0.1` — this is the address participants enter in their browser.

2. **Install Docker:** Make sure [Docker](https://docs.docker.com/engine/install/) and the `docker compose` plugin are installed.

### 3. Download the project & map tiles

1. Clone this repository to your Raspberry Pi:
```bash
git clone https://github.com/severinbro/pace-routing.git
cd pace-routing
```

2. Download the OpenStreetMap data for your target region and name it `region.osm.pbf` (e.g. from [Geofabrik](https://www.geofabrik.de/)). Place this file directly into `./data/maps/`. The tile server parses this file on first startup.

> **First run of the tile server:** The initial import of the `.osm.pbf` file can take a long time depending on the region size. On subsequent starts the tile server skips the import and serves cached tiles. If you need to re-import, remove the `tile-db-data` volume: `docker compose down -v`.

### 4. Generate the TLS certificate

The browser's Geolocation API requires HTTPS. A self-signed certificate is generated for the Pi's hotspot IP:

```bash
bash generate_cert.sh
```

This creates `nginx/certs/pace.crt` and `nginx/certs/pace.key`, valid for 10 years and covering the IP `10.42.0.1`.

> **Note:** On first visit, the phone's browser will show a "Your connection is not private" warning. Tap **Advanced → Proceed to 10.42.0.1 (unsafe)**. This is normal for self-signed certs on a private network — you only need to do this once per browser.

### 5. Launch the system

Build and start all containers. The `privileged: true` flag and device mappings in `docker-compose.yml` automatically pass the I2C buses and USB microphone into the `sensor_worker` container.

```bash
docker compose up --build -d
```

The `web` container waits for PostgreSQL to be ready, runs migrations automatically, then starts Gunicorn. Follow the logs to confirm everything came up cleanly:

```bash
docker compose logs -f web sensor_worker db_writer
```

### 6. Create an admin account

The `web` container runs migrations but does **not** create a user. You need one admin (`is_staff`) account to access the dashboard, map, and data browser, and to act as the GNSS source:

```bash
docker compose exec web python manage.py createsuperuser
```

Participants can either self-register via `/sign-up/` or be created by the admin via `/create-user/`. Participant accounts are non-admin (`is_staff=False`) and can only access the survey.

### 7. Access the platform

On any smartphone connected to the Pi's `pace` Wi-Fi, open:

**`https://10.42.0.1:8000`**

- **Participants** are taken straight to the survey after logging in / signing up.
- **Admins** are redirected to `/admin-home/`, from where the dashboard, map, and data browser are reachable.

Other endpoints (only reachable from the hotspot network):

| URL | Purpose |
|-----|---------|
| `http://10.42.0.1:8080` | Map tile server (used internally by Leaflet) |
| `http://10.42.0.1:5050` | pgAdmin (login: `admin@pace.io` / `pace`) |
| `http://10.42.0.1:8081` | HTTP redirect to HTTPS |

### 8. GNSS & system time

When an admin signs in on their smartphone, the browser continuously pushes the phone's GPS coordinates to the Pi via the Geolocation API (`/api/update-gnss/`). These coordinates are used for:

- Live position on the map
- GNSS snapshots attached to survey responses
- Synchronizing the Pi's system clock (the admin phone's GPS time is authoritative — the Pi has no RTC and no internet for NTP)

Only the admin phone provides GNSS data — participant phones do not interfere.

## Data model

All sensor and survey data lives in PostgreSQL. Tables are written together per reading (sharing an `id`), which makes the GeoPackage export a simple join.

| Model | Source | Key fields |
|-------|--------|------------|
| `GNSSPhoneMeasurement` | Admin smartphone browser | lat, lon, alt, satellites, accuracy |
| `GNSSSensorMeasurement` | SAM-M10Q over I2C | lat, lon, alt, satellites |
| `AtmosphericMeasurement` | BME280 | temperature, humidity, pressure |
| `AccelerometerMeasurement` | LIS3DH | accX/Y/Z, angleX/Y/Z |
| `AirQualityMeasurement` | ENS160 | aqi, tvoc, eco2 |
| `ParticulateMeasurement` | PMSA003I | pm1, pm25, pm10 |
| `NoiseMeasurement` | USB microphone | noise_db |
| `EnvironmentSurvey` | Participant input | q1–q11 (7-point Likert), `user`, `gnss_snapshot` |

## Stopping & maintenance

```bash
# Stop all containers (data persists in volumes)
docker compose down

# Stop and delete data volumes (PostgreSQL, tile server cache, pgAdmin)
docker compose down -v

# Rebuild after changing requirements.txt or Dockerfile
docker compose up --build -d

# View live logs
docker compose logs -f

# Tail a single service
docker compose logs -f sensor_worker
```
